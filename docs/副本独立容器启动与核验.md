# 副本独立容器：启动、核验与边界

日期：2026-09-24。仅适用于 D:\Study\LR-Agent-LangChain-Migration。

## 结论与边界

副本 Docker 项目名为 **lr-agent-migration**，原项目名为 **lr-agent**；两套可同时运行。四个副本容器承接云端 API、PostgreSQL、Redis、MinIO。**迁移后的 LangChain local-agent 不在这些容器里**，它仍由本机 Python/Electron 启动。容器健康不等于候选 Agent 的真实 GUI 验收。

只使用 LR-Agent-backend\docker\docker-compose.migration.yml。不得在副本使用旧 docker-compose.yml、docker-compose.override.yml 或旧启动/停止脚本；旧脚本在副本目录中已设置为 fail closed。

| PostgreSQL volume | lr-agent_lr-agent-pg-data | lr-agent-migration-pg-data |

| MinIO volume | lr-agent_lr-agent-minio-data | lr-agent-migration-minio-data |
| API image | lr-agent-api | lr-agent-migration-api:local |

所有副本端口只绑定 127.0.0.1，不暴露到局域网。

## 凭据与数据

副本凭据存放于 LR-Agent-backend\docker\.env.migration，不复用原项目凭据。该文件由 scripts\New-MigrationEnv.ps1 生成独立随机密码和 SECRET_KEY，已被 Git 忽略。生成脚本在文件存在时拒绝覆盖；不要复制、打印、提交或粘贴该文件。Compose 需要本地明文环境文件；若本机多人共享，另设文件访问权限/凭据托管。

更换数据库密码不等于自动更新已初始化的 PostgreSQL 数据卷，不能通过随意改 .env.migration 来轮换。不要执行 docker compose down -v；它会删除副本数据卷。

## 常用命令

首次生成凭据（本副本**已经执行过**，无需重复）：

~~~powershell
& 'D:\Study\LR-Agent-LangChain-Migration\scripts\New-MigrationEnv.ps1'
~~~

启动或重启副本容器：

~~~powershell
& 'D:\Study\LR-Agent-LangChain-Migration\scripts\start-migration-containers.ps1'
~~~

只停止副本容器并保留数据卷：

~~~powershell
& 'D:\Study\LR-Agent-LangChain-Migration\scripts\stop-migration-containers.ps1'
~~~

查看状态和 API 日志：

~~~powershell
Set-Location 'D:\Study\LR-Agent-LangChain-Migration\LR-Agent-backend\docker'
docker compose --env-file .env.migration -f docker-compose.migration.yml ps
docker compose --env-file .env.migration -f docker-compose.migration.yml logs --tail=80 api
docker compose ls
~~~

静态校验使用 config --quiet，避免普通 config 将解析后的凭据输出到终端：

~~~powershell
docker compose --env-file .env.migration -f docker-compose.migration.yml config --quiet
~~~

健康检查：

~~~powershell
Invoke-WebRequest 'http://127.0.0.1:18000/health' -UseBasicParsing
Invoke-WebRequest 'http://127.0.0.1:19000/minio/health/live' -UseBasicParsing
Invoke-WebRequest 'http://127.0.0.1:8000/health' -UseBasicParsing
~~~

预期均为 HTTP 200：18000 是副本 API，8000 是原 API。副本 API、Postgres、Redis 在 Compose 状态中应为 healthy；MinIO 用其 HTTP health/live 判断。
