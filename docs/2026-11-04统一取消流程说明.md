# 聊天取消流程统一（2026-11-04）

用户点击停止后，统一中止原聊天请求。后端关闭该请求持有的业务事件流，不再维护第二份按任务 ID 保存的取消 Event。

## 修改前的用途审计

- 仓库内的桌面前端没有调用 `/api/v1/agent/chat/cancel`。停止按钮调用 `stopGeneration()` → `stopJob()` → `AbortController.abort()`。
- 生产代码只有旧取消接口调用对应 Event 的 `set()`；默认引擎和 legacy 负责创建、读取和清理登记。其他生产模块没有设置入口。
- `ChatCancelRequest` 仅为旧取消接口服务，因此随接口移除。
- 业务循环中的 `is_cancelled` 钩子被 legacy 工具循环、只读子代理和迁移测试复用，因此保留。默认实现改为检查当前 asyncio 任务取消状态，并提供取消调度点，不再查询独立 Event。
- `client_job_id` 仍参与客户端任务与本次运行的关联，不能随着取消接口删除。
- 流关闭、后台读取任务取消、客户端审批撤销和终端进程停止均有独立用途，继续保留并验证。
- 两个实验脚本原先直接访问 Event 登记表，已调整为任务取消或内部测试钩子。旧阶段记录保留历史描述，以本说明和当前源码为准。

## 统一后的执行链

```text
停止按钮
→ AbortController 中止原聊天请求
→ HTTP 响应层感知断连
→ ClosingStreamingResponse 取消并等待所属的业务读取任务
→ 各包装层显式关闭下层生成器
→ 原始 Agent 读取任务、并行子流和模型连接执行清理
```

`app/core/streaming.py` 集中实现生命周期辅助器。响应层使用一个有明确归属的 asyncio 读取任务，避免 HTTP 层的 AnyIO 持续取消反复打断第三方生成器的异步清理。任务的读取队列只预取一帧，客户端接收变慢时保留背压。

`closing_stream()` 明确流的关闭责任。清理阶段暂时屏蔽外层取消，确保后台读取任务被等待、下层流被关闭；真实关闭错误继续传播。这与 [AnyIO 的资源清理说明](https://anyio.readthedocs.io/en/stable/cancellation.html#finalization) 一致。

真正的请求取消传播取消异常，不额外生成成功结束事件。迁移测试保留的内部布尔钩子仍可模拟协作式早停，但不再对应一个桌面端取消接口。

客户端终端工具继续使用同一 AbortSignal：等待审批时清理审批，运行时请求主进程终止命令。本次还补上了启动窗口：如果停止发生在 `bridge.start()` 返回之前，注册监听后会检查已中止状态，立即终止刚启动的命令。

## 能力边界

取消可以结束异步等待、停止后续轮次、关闭事件读取任务；Python 无法强制杀死已经在线程中执行的同步函数。对应测试确认请求可以先退出，线程结束后不会再继续启动模型轮次。

对已完成的文件、标注或外部服务操作，停止不会自动回滚。外部服务已经受理的工作是否能停止，仍取决于其自身取消协议。

本次移除了旧取消地址，该地址现在返回 404；前端沿用现有停止按钮，无需新增请求。服务进程需加载更新后的代码才会生效。
