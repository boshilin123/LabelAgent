# LR-Agent 日常启动与故障排查

## 启动

先启动 Docker Desktop，然后在自己的 PowerShell 中运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\Study\LR-Agent\scripts\start-lr-agent.ps1
```

此窗口必须保持开启。停止桌面端时在窗口中按 `Ctrl+C`。

固定端口是 renderer `1212` 和后端 API `8000`。MCP 与 local-agent 每次启动会选择当前空闲端口，以启动日志显示的 URL 为准。

需要逐层学习或调试时，按 [手工逐步启动与调试](手工逐步启动与调试.md) 操作。

## 查看状态

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\Study\LR-Agent\scripts\status-lr-agent.ps1
```

## 停止后端容器

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\Study\LR-Agent\scripts\stop-backend.ps1
```

`docker compose stop` 保留数据库和配置数据；不要用 `down -v`，后者会删除 volumes。

## 常见问题

### 1212 端口已占用

通常表示上一次 renderer 仍在运行。不要连续重复执行 `npm start`。先关闭旧 LR-Agent PowerShell/Electron 窗口，再检查状态。

### Electron 下载卡住

本机脚本已设置 `ELECTRON_MIRROR` 和工作区 `ELECTRON_CACHE`。不要改用系统级缓存目录。

### Electron 进程启动但没有窗口

请从当前登录用户自己的 PowerShell 运行启动脚本。后台服务会话可能无法把 GUI 显示到当前桌面，这是 Windows 会话隔离造成的，不是编译失败。

### Docker Hub 认证超时

本机已通过 `docker-compose.override.yml` 与 `Dockerfile.local` 使用 Quay/ECR fallback。它们是部署适配文件，不是业务代码。

### 注册返回 422

密码至少 8 位，并同时包含大写字母、小写字母和数字。当前上游 UI 可能只显示笼统错误，可结合 API 容器日志确认。

### 注册成功但收不到验证邮件

本机 `docker/.env` 默认没有 SMTP 主机、账号和授权码。后端检测到 `SMTP_HOST` 为空时会进入 mock 模式：账号和验证令牌仍正常写入 PostgreSQL/Redis，但邮件只记录到应用日志，不会投递到真实邮箱。

如需真实邮件，应配置一个可发信的 SMTP 账号：`SMTP_HOST`、`SMTP_PORT`、`SMTP_USER`、`SMTP_PASSWORD`（通常是邮箱生成的 SMTP 授权码）、`SMTP_FROM` 和 `SMTP_USE_TLS`，然后重新创建 API 容器。不要把授权码提交到 Git。

本地学习阶段也可以继续使用未验证账号登录；不要为了测试邮件直接修改数据库中的 `email_verified`。

### CPU 自动标注较慢

这是预期行为。当前目标是验证调用链；批量任务或 SAM2 性能优化留到后续 GPU 服务化阶段。

### DeepSeek 配置

当前默认 provider 为官方 `https://api.deepseek.com` 的 `deepseek-flash`。Key 保存在 Electron safeStorage 中，不要把 Key 写进 `.env`、文档或仓库。更换 Key 时优先在“大模型配置”界面编辑 provider。
