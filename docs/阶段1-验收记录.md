| API | 位置 | 说明 |

| `ToolRuntime` | `langgraph/prebuilt/tool_node.py:1663`；经 `langchain.tools.ToolRuntime` 导入 | `langchain.agents.middleware` **不**导出它（实测 ImportError）；形参名 `runtime` 自动注入且不进 tool schema（已断言） |

**实测事件形状**：直接 `astream(stream_mode="messages", version="v2")` 的外层信封是 v2 字典，但 `data[0]` 仍是 **v1 形状**的 `AIMessageChunk` / `ToolMessage`（依据 `pregel/_messages.py:268-272`、`main.py:2813-2820`）；`ToolMessage` 在直接 astream 下**也会出现**。此结论与阶段 4 备忘 §1 一致，并进一步证实其"双源按 `tool_call_id` 去重"的必要性。

**实测坑（已写入测试注释）**：`create_agent` 在**模型节点执行时**才 `bind_tools`（`factory.py:1432`），且 `bind_tools` 返回**新模型对象**；假模型的可观测状态必须放在跨浅拷贝共享的容器里，否则计数丢失。

## 5. 遗留问题与对文档的修正

1. **候选测试必须用 `importorskip` 守卫**（`tests/test_langchain_runtime_stage1.py:36` 的 `pytest.importorskip("langchain")`）：否则 baseline 环境会在采集期报 `ModuleNotFoundError`，直接破坏阶段 0 门槛。约定已回写阶段 0 记录 §1.1。
2. **`bind_tools_calls` 不可作为对照断言**：候选每次模型调用都会 `bind_tools`（`factory.py:1432`）且返回新对象，旧路径只在开头 bind 一次。阶段 2/4 对照须改用 **`bound_tool_names` 稳定性**（阶段 2 备忘 §7 风险 1）。
3. **`ToolMessage.status` 会不同**：官方中间件置 `"error"`，旧路径默认 `"success"`（阶段 2 备忘 §7 风险 2）；对象级比较需规避。
4. **`ToolRuntime` 命中数由 0 变 1**：阶段 0 记录 §8-10 的「0 命中」现指**生产 registry 工具**；候选测试工具新增 1 处命中，并在 `messages` 流模式下触发**外观性** pydantic 序列化告警（`PydanticSerializationUnexpectedValue ... field_name='context'`，来自 `langgraph/prebuilt/tool_node.py` 的 runtime 注入路径）。测试按类别 `filterwarnings` 忽略，**未**为消警告而删除 `runtime:` 形参。已存项目记忆 `ins_1b579cbe`。生产路径不出现该告警。
5. **阶段 2 的接入点已由 S1 指定**：给 `build_langchain_agent` 增加 `middleware: Sequence[AgentMiddleware] = ()` 并透传；以 `after_model` 注入 `ToolMessage` + `wrap_tool_call` 短路，取代当前的 `client_tool_names` 早停（`factory.py:1953-1964` 会按 `tool_call_id` 剔除 pending）。
