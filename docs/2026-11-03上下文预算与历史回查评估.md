# 2026-11-03 会话上下文预算、摘要保护与历史回查评估

## 本轮落实的规则

用户确认采用 token 策略：已知模型窗口时，使用窗口的 80% 作为会话输入预算；不再因为超过 20 轮就直接删除本轮携带的旧消息。20 轮配置用于摘要后保留近期完整轮次的参考，默认约保留 10 轮，必要时为满足预算进一步缩小。

预算来自 `contextBudget.ts::deriveMaxContextTokens`，移除了原先 10%、8K 下限和 48K 上限。窗口为 1,000,000 时预算为 800,000；接口如果返回 1,048,576，则预算为 838,860。窗口未知时沿用明确的 12,000 兜底，不把估计值标成真实探测结果。

发送前通过已有模型探测 IPC 读取 `/models` 的 `context_window`、`context_length` 或 `max_model_len`；优先保留用户手填值，其他探测结果短时缓存 5 分钟。补充了 `deepseek-flash` 官方别名的名称兜底，接口返回的真实数值优先于该兜底。探测过程中若用户改成手填配置，不覆盖新配置。

## 不遗漏未摘要历史的保护

- 正常 token 策略在预算充足时保留所有尚未被摘要覆盖的历史，包含超过 20 轮的短对话。
- 显式使用轮数策略时，即将移出窗口的未摘要内容也会触发摘要，不再只检查 token 阈值。
- 重新打开会话后，发送前按需从现有 SQLite 分页接口补齐未摘要消息；不依赖界面当前只显示的一页历史。内存中刚编辑的消息优先于数据库旧值。
- 分段边界对齐用户消息，连同该轮助手和工具记录一起保留，不从一问一答中间切开。
- 摘要输入读取完整的旧消息和工具记录，不套用正常请求仅回放最近若干条助手工具历史的限制。
- 摘要全部成功、内容非空且压缩后估算仍在预算内，才返回新覆盖点。失败时不推进覆盖点、不删除数据库原文。
- 摘要失败但原文仍在预算内时继续使用原文；已超预算时显示可重试错误并结束准备状态，不静默丢消息，也不继续发送明显超预算的请求。
- 摘要模型按自己的窗口分批合并历史，支持辅助模型比主模型窗口小的情况。只有全部批次成功，才提交最终摘要。

token 统计仍是保守近似：英文约字符数/3，中文等非 ASCII 字符按 1，补充字符按 2，并计入序列化的工具调用和结果。这不是所有模型通用的精确 tokenizer。模型的系统提示、动态工具和输出还会占用上下文，本轮没有进行 80 万 token 的真实满载压测或性能优劣对照。

## 影响范围与兼容性检查

HTTP 请求继续采用既有 `messages`、`context_summary` 和客户端结果协议。SQLite 使用已有消息、摘要和模型窗口字段；未新增向量库或迁移业务表。Python Agent 核心、标注应用和人工确认协议由原回归覆盖。

启动时还复现了宿主环境兼容问题：`ELECTRON_RUN_AS_NODE=1` 使 Electron 无法作为桌面应用运行，`DEBUG=release` 使 Python 布尔配置解析失败。启动脚本只在自身进程环境中清除前者，并将不合法的 DEBUG 值改为 false；不修改系统环境变量。

## 历史原文回查是否值得增加

本轮增加的是“正常发送前补齐未摘要原文”，不是“按新问题自动检索已摘要的旧会话”。在 80% 预算内，第 30 轮询问第 2 轮细节时，相关原文通常仍能随本轮消息携带。跨过摘要覆盖点后，摘要没有保留的细节依然需要原文回查。

原始数据、会话与消息 ID、排序索引、时间和分页 IPC 已具备，可以基于现有 SQLite 开发，不需要向量数据库。

按单人开发及验收估算，最小可用版约 1～2 个工作日：

1. 为同一会话提供按消息 ID、时间、关键词的受限原文查询，检查会话归属、限制返回量。
2. 支持明确的“回看第 N 轮/查找某个参数”引用，保留原文来源标记。
3. 按预算回填相关用户、助手与工具消息，去重，并保护当前任务输入。
4. 补充编辑/重试后的轮次映射、空结果、预算不足和端到端回归。

进一步实现自动判断是否回查、相关性排序和效果评价，另估 2～3 个工作日。自然语言指代、旧结论被新结论覆盖、摘要与原文冲突、查询结果误相关，都是需要真实样例验证的部分。这是静态源码估算，不是工期承诺。

建议先做可确定的同会话回查。长会话学习、需要精确引用参数或决定的场景值得投入；以短标注任务为主时，可以先观察本轮更大原文窗口的使用效果，再决定是否增加自动回查。
