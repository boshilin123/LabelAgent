# LR-Agent Windows 本地部署方案

## 目标

在 `D:\Study\LR-Agent` 建立可长期用于学习、调试和二次开发的 LR-Agent 环境。桌面端、Agent 编排和 CPU 推理在 Windows 本机运行；账号后端及 PostgreSQL、Redis、MinIO 运行在 Docker Desktop。

## 目录规划

```text
D:\Study\LR-Agent
├── .venvs
│   ├── lr-agent-local
│   ├── lr-agent-inference
│   └── .runtime        # 缓存、日志、模型测试文件，统一隐藏在这里
├── docs
├── scripts
├── LR-Agent
└── LR-Agent-backend
```

顶层只保留两个仓库、虚拟环境、文档和脚本五个目录。npm、pip、Electron、Ultralytics、Matplotlib 缓存以及测试数据统一放在 `.venvs\.runtime`。

## 运行架构

```text
Electron / React
├── spawn: lr-agent-local (FastAPI + LangChain)
├── spawn: lr-agent-inference (CPU PyTorch / YOLO / SAM2)
└── HTTP: LR-Agent-backend :8000
    ├── PostgreSQL :5432
    ├── Redis :6379
    └── MinIO :9000 / :9001
```

LLM 通过 OpenAI-compatible API 远程调用。API Key 仅保存在 Electron safeStorage 加密的本机数据中，不写入仓库或文档。

## 实施顺序

1. 检查 Git、Python 3.12、Node.js、npm、Docker Desktop。
2. 创建两个互相隔离的 Python venv。
3. 使用 CPU requirements 安装 inference。
4. 使用 `npm ci` 安装锁定的前端依赖。
5. 在后端 `docker/.env` 配置本机密码和随机密钥。
6. 构建并启动四个 Docker 容器。
7. 验证后端健康、Python import、inference ping。
8. 启动 Electron，由 Electron 自动拉起两个 Python 子服务。
9. 配置 DeepSeek provider，测试普通对话、多模态和 Tool Calling。
10. 使用小图片测试 CPU YOLO 自动标注。

## 本机网络兼容策略

- PyPI 较慢时使用清华 PyPI 镜像。
- Electron 二进制使用 npmmirror，并把缓存放在工作区。
- Docker Hub MinIO 不可用时使用 Quay 官方镜像。
- Docker Hub Python 基础镜像认证超时时，使用 AWS Public ECR 的同名官方镜像。

这些兼容项只放在本机 override/Dockerfile 中，不替换上游源码文件。

## 验收标准

- 四个 Docker 容器运行，PostgreSQL、Redis 为 healthy。
- `http://127.0.0.1:8000/health` 返回 `status=ok`。
- local-agent 的 FastAPI/LangChain/OpenAI/MCP 关键依赖可导入。
- inference 返回 `torch=2.5.1+cpu`、`cudaAvailable=false`，YOLO/SAM2 等依赖可导入。
- Electron 可见窗口正常出现，1212 端口监听。
- 注册、登录、DeepSeek 普通对话、多模态和至少一次 Tool Calling 成功。
- CPU YOLO 能对测试图片返回检测结果。
