# 新用户首次跑通 LR-Agent 流程

现阶段目标是先理解并跑通 Agent 的“读取上下文 → 调用工具 → 提出修改 → 人工确认”闭环。数据标注、邮件投递、向量检索先不作为入门阻塞项。

## 一、启动并检查服务

先启动 Docker Desktop，再执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\Study\LR-Agent\scripts\start-lr-agent.ps1
```

另开 PowerShell 检查：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\Study\LR-Agent\scripts\status-lr-agent.ps1
```

至少确认：后端为 `ok`、local-agent 为 `ok`、Electron 窗口已出现。

## 二、确认大模型

在左侧打开“大模型配置”，确认：

- 名称：DeepSeek
- 模型：`deepseek-flash`
- 状态：启用
- 默认模型：是

API Key 不在项目 `.env` 中。它位于 `%APPDATA%\lr-agent\lr-agent.db` 的 `llm_providers` 表，并由 Electron safeStorage 加密；应用读取时才通过 Windows 用户凭据解密。

## 三、先跑通自动标注主链路

点击左侧“打开文件夹”，选择：

```text
D:\Study\LR-Agent\demo\label
```

切换到 Agent 模式，先明确指定业务权重和置信度，例如：

```text
请使用 D:\Study\LR-Agent\weights\label.pt 对当前工作区的图片执行自动标注，置信度先设为 0.35。先说明计划，再调用工具；完成后汇总成功检测、无检测和失败的图片数量。
```

预期链路是：自然语言任务 → DeepSeek 规划 → `auto_annotate` → YOLO CPU 推理 → 标签映射 → 候选标注 → 写入标注。无检测结果不等于执行失败；如果多数图片没有框，可依次尝试 `0.20`、`0.10`，并人工检查误检情况。

当前已经实测该链路可完整执行。一次 15 张图片、置信度 `0.35` 的测试中，2 张产生并应用了标注，13 张无检测结果。

## 四、打开安全的代码练习工作区

点击左侧“打开文件夹”，选择：

```text
D:\Study\LR-Agent\demo
```

不要一开始就让 Agent 修改 LR-Agent 主仓库。可在 `demo` 下新建一个小型代码练习目录，熟悉 Ask、Agent、工具调用和变更确认。

## 五、先跑 Ask 模式

保持输入框左侧模式为 `Ask`，依次发送：

```text
请读取当前工作区，列出文件，并说明这个练习项目要做什么。不要修改文件。
```

```text
请读取 calculator.py，指出代码中有什么问题，并给出修复建议，但不要修改。
```

这里重点观察：

1. 模型是否调用 `list_workspace_directory`、`read_workspace_file` 等工具；
2. 工具调用过程是否显示；
3. Ask 模式是否只分析、不写文件。

## 六、跑 Agent 修改闭环

把模式切换为 `Agent`，发送：

```text
请修复 calculator.py 中的除法问题，补充必要的类型提示，并更新 学习任务.md 中的完成状态。修改前先读取相关文件。
```

预期流程：

1. Agent 读取文件；
2. Agent 调用写文件或文本替换工具；
3. 界面展示修改提案；
4. 你检查差异；
5. 只接受你认可的修改。

这一步是当前最重要的学习闭环。

## 七、验证工作区搜索

继续在 Agent 模式发送：

```text
请搜索工作区中所有包含 TODO 的位置，汇总后写入 TODO汇总.md。
```

重点观察 `grep_workspace`、`glob_workspace`、`write_workspace_file` 的选择与参数。

## 八、再进入项目源码学习

练习流程稳定后，再把工作区切换为：

```text
D:\Study\LR-Agent\LR-Agent
```

建议先用 Ask 模式完成这些任务：

1. 解释 Electron renderer 如何调用 preload IPC；
2. 追踪一条 Agent 消息从 UI 到 local-agent 的调用链；
3. 列出 Agent 可用工具及其权限；
4. 解释 Ask 与 Agent 模式的安全边界；
5. 解释 MCP、Skill、工作区记忆分别解决什么问题。

## 九、理解各标注模型的职责

自动标注主链路跑通后，再区分不同模型的职责：

1. 创建图片标注项目；
2. 矩形框使用 YOLO 检测；
3. 多边形流程通常先用 YOLO 找目标，再用 SAM2 根据框生成轮廓；
4. 人体关键点使用 YOLO-Pose，手部可用 MediaPipe，人脸可用 face-alignment；
5. 检查预标注结果后再人工确认与修正。

当前 `yoloe-11s-seg.pt` 可以被 Ultralytics 加载，但 LR-Agent 现有适配层没有设置 YOLOE 文本提示，也不读取 segmentation masks。实测在测试图片上返回 0 个框，因此暂时不能作为“开箱即用”的 YOLOE 分割模型；需要后续单独增加 YOLOE prompt 和 mask 适配。

DeepSeek 的图片理解工具与 YOLO 检测也不是同一件事：前者用于让 Agent 理解图像内容并规划操作，后者负责输出可落盘的检测框或分割结果。

## 首次跑通的验收标准

- Ask 能读取并解释练习工作区；
- Agent 能提出文件修改；
- 你能查看并确认修改；
- 搜索工具和写入工具均至少成功调用一次；
- 新会话可以选择默认 DeepSeek 模型；
- 知道如何查看启动日志和整体状态。
- 能用 `label.pt` 跑通一次自然语言驱动的自动标注，并区分“无检测”与“执行失败”。
