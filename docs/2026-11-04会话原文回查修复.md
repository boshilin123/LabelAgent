# 已压缩会话的原文回查（2026-11-04）

摘要省略某个数值、文件名或决定后，发送下一条消息前会从当前用户、当前会话的 SQLite 记录中查找相关原文，再把带来源的引用补入本轮模型请求。摘要依然用于概览，近期原文正常携带，回查内容只在本次任务中使用。

## 当前支持的定位方式

- 关键词，例如“之前确定的检测阈值是多少？”、“之前 LearningRate 怎么设置？”。
- 用户轮次，例如“第二轮说了什么？”、“回看第 12 轮”。轮数按用户消息分组计算，不把数据库排序索引当作轮数。
- 消息 ID，例如“消息 ID: msg-…”，也识别应用生成的消息 ID 和 UUID。
- 文件路径，包括历史工具参数中的 Windows 路径、重命名前的路径。

关键词回查采用本地字面匹配和相关性排序。它不保证识别完全不同措辞或缺少定位线索的指代；明确回查却没有命中时，会把未命中的范围说明交给模型，要求先检查近期原文，仍无依据就说明无法确认或请求更多线索。

## 文件与职责

- `src/shared/conversationHistory.ts`：解析 ID、轮次、关键词；提取保存内容；截取关键词附近的原文。
- `src/main/db/historyRepository.ts`：校验用户、会话与摘要边界，在 SQLite 中检索原文并补充同轮上下文。查询只读，不新增数据库表。
- `src/main/db/handlers.ts`、`src/main/preload.ts`、`src/renderer/services/agentChatApi.ts`：连接有明确归属的回查 IPC。
- `src/renderer/services/historyRecallContext.ts`：按 token 上限组织来源引用，注明消息 ID、轮次、时间和是否只提供片段。
- `src/renderer/services/contextPreparer.ts`：回查已摘要原文；如果本轮新触发压缩，也查询新移出窗口的范围，并核算整个输入预算。
- `src/renderer/services/agentJobRegistry.ts`：把只读引用送入普通聊天和工具型 Agent 请求；工具续跑继续沿用这份引用，不重放旧工具调用 ID。

## 预算、原文和业务状态

token 数量沿用项目现有的保守估算，并非所有模型通用的精确 tokenizer。

模型窗口的 80% 仍是整份会话输入预算。回查引用包含在其中，上限为总预算的 10%，小窗口允许至少 512 token、大窗口最多 8192 token，且不超过总预算。这只是回查材料的上限，并非把历史窗口改成 10%。实际按最终引用文本计费，不为了预留最大额度而提前移出一整轮近期原文。

每次最多选取 4 轮、每轮最多 8 条消息。长消息优先保留关键词附近原文，先缩短片段、再考虑减少选中轮次，尽量保留后续更正。片段及省略记录数有明确标记，选中的记录按会话顺序提供。字面匹配忽略 JSON 字段名和推理块，避免 `content` 等存储元数据挤掉真正的原文命中。

数据库原始消息和已保存摘要不因回查而修改。回查引用不会写入新的会话消息，也不会被混入下一次摘要。内存中版本更新的编辑优先；相同时间戳的界面预览不覆盖数据库原文。

旧工具记录、文件提案只作为证据，不自行授权执行或应用。用户当前明确要求操作时，仍须依据当前业务状态发起新的工具调用。当前配置以业务数据为准；回查用于说明当时记录了什么。
