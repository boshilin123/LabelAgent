# LR-Agent Windows 本地部署方案

更新日期：2026-10-17。当前工作目录为 `D:\Study\LR-Agent`，默认引擎为 `candidate`（官方 `create_agent`，底层 LangGraph）。不再使用已清理的独立迁移副本。

本项目不集成 RAG、向量知识库或向量数据库。目标是运行并理解“自然语言指令 → 工具调用 → 本地推理 → 提案 → 人工确认 → 应用标注”。

## 1. 前提与目录

需要 Windows、Python 3.12、Node.js 22、npm、Git / Git LFS、Docker Desktop（Linux containers）。脚本当前按 `D:\Study\LR-Agent` 配置；如更换目录，需同步调整启动、状态检查和停止脚本中的工作区路径。

```text
D:\Study\LR-Agent
├── .venvs
│   ├── langchain-main       # 正式 Agent 编排，不装 torch
│   ├── lr-agent-inference   # 本地 CPU 推理
│   ├── langchain-studio     # 可选调试环境
│   └── .runtime            # 缓存、日志和可选追踪凭据，不提交
├── LR-Agent
├── LR-Agent-backend
├── demo
├── weights
├── docs
└── scripts
```

执行 `git lfs install`、`git lfs pull` 获取跟踪的模型。`BottleCap.pt` 等本机专用模型不随仓库分发；首次验收可使用仓库中跟踪的 `weights\label.pt` 和 `demo\label`。

## 2. 安装正式 Agent 环境

```powershell
cd D:\Study\LR-Agent
py -3.12 -m venv .venvs\langchain-main
.\.venvs\langchain-main\Scripts\python.exe -m pip install -r LR-Agent\vendor\local-agent\requirements.txt
.\.venvs\langchain-main\Scripts\python.exe -m pip check
```

正式清单固定 `langchain==1.4.2`、`langchain-core==1.6.4`、`langgraph==1.2.12`。不要使用早期仅有 `langchain-core==1.4.0` 的清单启动默认引擎。历史文件 `requirements-migration.txt` 现在引用正式清单，避免两份依赖漂移。

若升级现有环境，只执行安装与 `pip check`，不必重建 venv。`AGENT_ENGINE=legacy` 可用于旧路径对照，日常启动保持 `candidate`。

## 3. 安装 CPU 推理环境

```powershell
cd D:\Study\LR-Agent
py -3.12 -m venv .venvs\lr-agent-inference
.\.venvs\lr-agent-inference\Scripts\python.exe -m pip install -r scripts\requirements-cpu-no-sam.txt
.\.venvs\lr-agent-inference\Scripts\python.exe -m pip check
```

这个清单包含 CPU PyTorch / torchvision、Ultralytics 和现有推理依赖，**不包含 SAM2**。YOLO 矩形框主流程不依赖 SAM2；若需要 SAM2 多边形标注，再通过桌面环境向导安装匹配的 SAM2 环境与权重。不要把 SAM2 缺失误判成 YOLO 主流程失败。

单独检查推理协议：

```powershell
cd D:\Study\LR-Agent\LR-Agent\vendor\inference
$env:YOLO_CONFIG_DIR = 'D:\Study\LR-Agent\.venvs\.runtime\ultralytics'
$env:MPLCONFIGDIR = 'D:\Study\LR-Agent\.venvs\.runtime\matplotlib'
'{"cmd":"ping"}' | D:\Study\LR-Agent\.venvs\lr-agent-inference\Scripts\python.exe server.py
```

CPU 环境应报告 Python / torch / Ultralytics 可用，`cudaAvailable=false`；不要求所有可选模型后端均为 true。

## 4. 安装桌面端

```powershell
cd D:\Study\LR-Agent\LR-Agent
$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
$env:ELECTRON_CACHE = 'D:\Study\LR-Agent\.venvs\.runtime\cache\electron'
npm.cmd ci
```

保留默认安装脚本，它们会准备 Electron 与开发 DLL。正常使用根目录的一键启动脚本自动设置 Python 路径。

## 5. 初始化认证后端

先启动 Docker Desktop。在 `LR-Agent-backend\docker\.env` 中配置 PostgreSQL / Redis / MinIO 密码及随机 `SECRET_KEY`，变量名以同目录 `.env.prod.example` 与 Compose 文件为准。已有 `.env` 不要覆盖。SMTP 可留空，此时注册邮件进入 mock 模式，不实际投递。

```powershell
cd D:\Study\LR-Agent\LR-Agent-backend\docker
if (-not (Test-Path -LiteralPath '.env')) { Copy-Item .env.prod.example .env }
# 首次复制后先编辑 .env，设置本机密码和随机 SECRET_KEY，再继续执行。
docker compose up -d --build
docker compose ps
Invoke-RestMethod http://127.0.0.1:8000/health
```

数据库迁移由容器 entrypoint 执行。当前本机 override 使用 Quay MinIO 与 `Dockerfile.local` 的镜像源适配。四个服务为 `lr-agent-api`、`lr-agent-postgres`、`lr-agent-redis`、`lr-agent-minio`；PostgreSQL / Redis 应 healthy，API `/health` 应返回 `ok`。

一键脚本日常使用 `docker compose up -d --no-build`，所以首次必须先完成本步骤的镜像构建。

## 6. 启动桌面端与配置模型

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\Study\LR-Agent\scripts\start-lr-agent.ps1
```

脚本使用 `.venvs\langchain-main` 与 `.venvs\lr-agent-inference`，显式选择 `candidate`；启动 Docker 配套服务，再运行 Electron。保持终端开启，`Ctrl+C` 停止桌面开发进程。

- Renderer 固定端口 `1212`，认证 API 为 `8000`。
- MCP 和 Local Agent 使用动态空闲端口，以本次日志与状态脚本为准。
- Local Agent 监听 loopback，并要求启动时注入的 token；`/health` 无需 token。
- 首次进入“大模型配置”，填写支持 Tool Calling 的 OpenAI 兼容服务、模型名和 Key；现有本机使用 DeepSeek 配置。实际可用模型以提供商账号为准。
- 模型 Key 保存在当前 Windows 用户的 Electron safeStorage / 本地 SQLite 中，不经认证后端、不提交到 Git。

## 7. 可选 LangSmith / Studio

不需要追踪也能启动。脚本优先读取环境变量 `LANGSMITH_API_KEY`，未提供时读取 Git 忽略的 `.venvs\.runtime\langsmith-api-key.txt`。有效时启用现有 `lr-agent-local` 项目追踪；缺失或格式不符时关闭追踪并继续启动。

显式关闭：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\Study\LR-Agent\scripts\start-lr-agent.ps1 -DisableTracing
```

追踪启用时，对话与工具轨迹可能发送到 LangSmith，先用测试数据。Studio 为独立只读图调试入口，通常使用 `2025` 端口，不代表桌面自动标注/确认写盘已在 Studio 中实现。详见 [LangSmith-Studio-本地调试](LangSmith-Studio-本地调试.md)。

## 8. 主流程验收与日常检查

按 [新用户首次跑通流程](新用户首次跑通流程.md) 验证 Ask 读取、Agent 工具调用、YOLO 推理、提案审核、确认落盘及重启回读。无检测、标签映射失败和服务失败分别报告，不把提案生成称为已经写入。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\Study\LR-Agent\scripts\status-lr-agent.ps1
cd D:\Study\LR-Agent\LR-Agent\vendor\local-agent
D:\Study\LR-Agent\.venvs\langchain-main\Scripts\python.exe -m pytest -q
D:\Study\LR-Agent\.venvs\langchain-main\Scripts\python.exe -m experiments.compare_agent_contract
```

自动化回归不能替代真实桌面确认与文件核验。故障定位按 Docker → API → Local Agent → inference → Renderer 顺序，详见 [手工逐步启动与调试](手工逐步启动与调试.md) 与 [日常启动与故障排查](日常启动与故障排查.md)。
