# 副本桌面端启动与验收记录

日期：2026-09-24。范围仅为 D:\Study\LR-Agent-LangChain-Migration，原项目代码与原容器不改动。

## 启动方式

一键启动：powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\Study\LR-Agent-LangChain-Migration\scripts\start-lr-agent-migration.ps1。它顺序启动副本容器、等待 API 健康，再启动桌面端；保持该终端打开。按 Ctrl+C 退出桌面端后，可单独运行 scripts\stop-migration-containers.ps1 停止副本容器，数据卷保留。

桌面端将渲染服务绑定 127.0.0.1:1213，API 指向 http://127.0.0.1:18000/api/v1，本地 Agent 由 Electron 随机分配端口，用户数据与 SQLite 放在副本的 .venvs\.runtime\migration-user-data。独立用户数据目录也隔离了会话、模型提供商凭据、MCP 配置与 Electron 缓存；副本不会注册全局 lr-agent:// 协议处理程序。

副本启动脚本给本地 Agent 配置了精确的 CORS_ORIGINS：127.0.0.1:1213 和 localhost:1213。2026-09-24 曾发现默认配置只允许 localhost:1212，导致 /api/v1/agent/chat/stream 的 OPTIONS 返回 400；修复后测试客户端对两个副本来源均返回 200，对不在清单中的来源仍返回 400。修改启动脚本后必须退出并重新启动副本桌面端，已运行的 Agent 进程不会自动继承新环境变量。

当前为了完成桌面联调，副本使用原安装中相同版本的只读 Electron 可执行文件与原安装的推理 Python 解释器；应用数据、模型配置缓存、端口和容器并未共用。若下一阶段要求可单独搬迁的完整运行时，需要在副本内另装 Electron 二进制和 YOLO 推理虚拟环境，再改启动脚本的这两条路径。不要误称当前运行时二进制也完全独立。

## 2026-09-24 全项目自动标注失败诊断

在副本 demo/label 项目中，模型 weights/label.pt 的检测类为 normal_logo，项目唯一标签名为 label，保存的置信度阈值为 0.3。旧代码在没有显式阈值覆盖时，把 undefined 合并到模型参数上；发送到 Python 前序列化又会丢弃该字段，推理端退回默认 0.7。IMG_8164.JPG 的检测置信度约为 0.534，因此旧路径漏检；按应用实际逐张推理路径复现，缺省阈值返回 0 框，0.3 返回 1 框。

另一个原因是单标签项目默认仍走按检测类名匹配，normal_logo 与 label 不同而产生“无有效 label_id 映射”。副本现保留已保存的阈值，并在项目恰好只有一个标签时使用已有的单标签映射路径；多标签项目仍逐框映射。

对 22 张图片用相同模型与 0.3 阈值逐张只读推理：19 张有框，共 22 框；IMG_8165.JPG、IMG_8168.JPG、IMG_8178.JPG 仍无检测。这 3 张应如实报告为未检出，不会凭空生成标注。主进程与渲染进程构建通过；相关 10 个 Jest suite、56 个测试通过；单标签服务返回有效映射。尚未在 GUI 中重新执行并确认提案/落盘，不能称为最终验收。
